# 调用方上下文与受保护能力

MCP 仅提供 `token-io-decoupling-tools`，面向 Pi 使用标准 stdio，无需启动参数。已移除历史上的多服务 setup 与 workflow 程序。

普通工具发现、规则上下文查询、Serena Memory 只读检查不证明调用方拥有身份、任务分配或操作授权。Memory 路径范围固定为服务实际启动目录；需要读取目标项目时应在该项目目录启动服务，不搜索父目录或相邻仓库。

## 可信绑定边界

受保护材料化仍需要可信启动时注入的 `BindingProvider`、当前角色/分配与独立操作 grant。默认 stdio 不自动提供这些条件；未配置时返回不可用，不因服务支持 Pi 而降低检查。

Core 中的可选请求上下文匹配仅在显式启用且可信 `BindingProvider` 可用时作用于受保护操作。它要求请求元数据中的 `threadId` 与当前已验证会话 ID 一致；`sessionId` 等不透明请求字段不选择身份、角色或授权，也不能建立可信绑定。该匹配不为 Pi 会话提供身份适配。不得将 Pi 会话 ID、请求参数或自报角色伪装成可信绑定，也不得用不匹配的来源元数据伪造会话事实。

材料化约束见 [输出材料化](OUTPUT_MATERIALIZATION.md)；调用方上下文总览见 [开发指南](DEVELOPMENT.md#调用方上下文)。
