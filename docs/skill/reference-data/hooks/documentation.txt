# 文档、注释与可复用项目知识

## 触发条件

- 进入 documentation（DOC00–DOC06）、上报 `documentation_impact`，或已授权任务实际改变文档/注释/可复用项目 Memory。
- 用户请求项目知识持久化，或对应 owner 的知识/memo 触发条件成立；`write_content_memo: false` 不等于所有项目知识输出都不适用。
- 没有适用输出或批准输出确实无变化时，须有当前匹配指纹及原因才能记 N/A；缺授权、来源、路径、工具或检查不是 N/A。

## 输入与证据

当前 Contract/范围、已释放模式、实际 Session/作者职责、准确 continuation/已完成效果、待记录状态的当前 implementation/content Verification、写前指纹。存在适用输出时另须批准路径/Memory名称、读者、目的、来源证据、作者与写入授权；适用时提供准确候选、可信基线及计划指针。

## 执行要求

### 一、先核验当前状态与作者边界（DOC00–DOC01）

1. 核验入口所需事实、当前 Verification 和准确范围；来源检查过期/缺失则回相应 Verification，效果歧义先读回，不边写边猜测。
2. 按当前用户意图/Contract及owner触发条件逐项判断文档、注释、项目Memory是否适用；适用则取得准确路径、读者、目的、来源和作者授权，不能用缺少输入推成不适用。
3. 普通非 Skill 文档/注释由 Root/parent 编写，即使伴随代码变更也不创建或消耗 Primary 名额。只有本 Skill 指令/参考文档，在所有 release gates 通过后才可分配 Primary Output；Root仍在Documentation与Acceptance亲自审阅。
4. Documentation/Comments & Git Operations 职责只承接单独放行的非简单Git，不因名称含Documentation就获得普通文档或产品代码权限。
5. 需要实质语义选择、行为/政策/Contract/范围/验收变化时回调用方Decision路径；不能以“润色/补文档”自行作出新决定。

### 二、确认可选候选分支，再写批准输出（DOC02）

1. 可选候选预检确实未选择或条件不存在时，附原因记N/A，在独立授权的直接文档路径继续。已选择分支则必须准备准确有界候选及当前可信基线，不得因缺它们反标N/A。
2. Skill维护使用 `skill_maintenance`，其他项目用 `generic_project`；只对当前候选/基线运行选定结构检查，应用前解决失败、unknown、遗漏、截断及过期结果。不得以旧候选检查或普通写权限替代受保护路径守卫。
3. 预检只给有限候选证据，不证明中文语义、真实写后状态或最终Verification；细节按 [候选与物化合同](materialization.md)。选定路径实际失败不得换入口绕过。
4. 只根据当前已验证来源编辑已批准Markdown/注释路径，保留技术含义。检查用户可见说明、行为/配置/API、安装/使用步骤、限制、安全/权限承诺、故障处理、示例、链接、目录和注释的一致性。
5. 本仓库维护唯一中文权威，不新增语言镜像。只执行当前项目适用检查；本任务明确不使用双语维护检查，不把它当作前置。
6. 不以普通文件、capsule、任务计划或相邻路径替代缺失的权威文档/Memory输出；也不把权威README/规范迁入Memory作为替代品。正常直接文档用真实获准的read/edit/write等能力，不凭空要求物化专用适配器。
7. 没有输出差异须以前后指纹匹配证明。保留实际已写部分；恢复不重放DOC02。

### 三、独立处理可复用项目 Memory（DOC03）

1. 用户请求可复用项目知识或owner条件触发时，遵循 [上下文合同](context.md) 和对应知识/memo生命周期；优先已提供的精确名称，只有需发现时才列相关topic，不先浏览全部Memory。
2. 仅保存稳定、不显而易见、对后续任务有用且获准的项目知识/笔记，保留事实、范围、不确定性和准确权威指针；不复制来源全文、秘密、完整transcript、日志、私有推理或父级调度表。
3. 核对实际Serena项目绑定、维护说明、具名读写授权及真实Schema。默认项目Memory与 `global/` 范围分开；跨项目写入须明确要求，计划专用共享scope另按计划合同，不据此扩展一般知识授权。
4. 经真实Memory工具写入并确认操作成功，记录准确名称和结果。只有owner触发存储内容核验时才检查；有匹配核验凭据先用该凭据，否则作必要内容比较。普通成功write/edit不立即全文重读，不用理论上可能变化作为反复读回理由。
5. 未请求且未触发时记有原因的N/A。必需工具、持久化或要求的内容核验失败/不可用/未知，保持该请求输出未完成并阻断依赖；不回退普通文件。
6. `write_content_memo: false`只关闭该Worker memo，既不取消默认共享任务计划，也不能把用户请求的可复用项目知识改为N/A。

### 四、在所有实际输出后分类影响（DOC04）

1. 在文档和请求的Memory写入及必要核验后，对比写前/写后指纹，区分implementation/content、documentation和Git metadata维度。
2. 实际文档/注释/项目Memory变化按适用owner推进documentation epoch；确无输出变化且指纹相同则不推进，附证据记N/A。父级实时控制记录不是项目知识输出。
3. 可执行内容、Contract或Acceptance受影响时，也使implementation/content证据失效，回当前Verification；影响未知则阻断，不能为了保留通过状态强行标“纯文档”。
4. 仅文档维度改变时，对未变维度给出当前指纹及证据复用理由；不重跑无关行为测试。epoch/effect字段是影响报告，不认证语义分类；适配器无法表达必需状态时报告缺口，不伪称自动识别。

### 五、写后检查与返回（DOC05–DOC06）

1. 在所有文档/Memory写入后运行实际适用的Markdown结构、链接/标题锚点、空白、命名/范围及项目专用检查，核对注释与实现、文案与真实行为一致。
2. 检查通过须有当前实际结果；必需检查失败、未运行或不可用时保持未完成。无变化且指纹匹配才可对相应检查记N/A，不将工具成功或写前预检冒充写后检查。
3. 返回实际路径/Memory名称、来源、documentation fingerprint/epoch、检查结果、前后影响分类、未变证据复用理由及Memory核验结果/N/A。
4. 只有所有适用检查、必要持久化/存储核验及受影响内容Verification均解决，才能返回本模块complete；这不授权Git，也不等于整体验收。

## 退出与阻断

缺当前Verification/批准范围/作者/来源/Memory前置时交对应owner补证并保留暂停位置；范围冲突、作者越界、拒绝、影响未知或必需检查失败时阻断。部分写入、失败或未知效果先读回，不隐藏、不覆盖重放。对有依据的N/A给出触发条件不存在或指纹匹配证据。

## 重新核验

文档/知识内容、来源、作者、范围、授权、基线或当前epoch变化时只重核受影响条件。写后回验从DOC04影响分类继续，缺失检查在DOC05补齐，不重放DOC02或已确认的Memory写入。Acceptance必须使用最新适用维度证据。
