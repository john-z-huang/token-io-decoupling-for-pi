# 执行 Hook：Slice、Control 与阶段反馈

## 触发条件

当任务进入 coding execution、准备释放或恢复 Slice、执行者收到任务、到达返回条件/阶段边界、出现新事实或工具失败时适用。它是声明式动作合同，不是宿主回调、命令脚本或工具授权。Root 先读取当前 Contract、Decision、Context、模式/执行者、授权与效果状态；依据当前直接证据判断，不能把未知、未检查或调用成功等同于否。

每个准备执行的 Slice 必须可追溯到当前任务和明确授权。低决策密度且不越界的机械操作可在同一 Slice 连续完成；没有依赖、路径冲突及共享写入冲突的已释放工作方可并行。Slice 不是逐命令清单，亦不可借连续操作扩张授权。

## 执行要求

### 1. 建立可执行 Slice 与准入门

Slice 必须同时具有以下四字段，缺一不得释放：

| 字段 | 合同要求 |
| --- | --- |
| Objective | 描述本切片要达到的具体目标，不以工具调用或模糊愿望代替。 |
| Authorized scope / mutations | 明确允许的行为、精确路径/对象及可产生的变更；不得从目标推导额外文件、重构、外部影响或 Git 操作。 |
| Return conditions | 指定何种里程碑、证据、检查结果或阻塞状态必须返回；到达条件即停，不继续顺手扩展。 |
| Unreleased boundary | 明确仍未放行的子系统、路径、风险、语义选择、决策和后续效果；不得以“相关”推定已放行。 |

准入前核实任务授权、模式、当前 Root/Worker 身份和权限、Context/Decision 新鲜度、Slice 与 Contract 一致、返回条件及依赖证据可取得。对 Worker 还要核实当前 Session allocation、角色、能力、可用性和父级已释放任务；不接受过期或不同 Session 的身份/授权。任何冲突、未知的必需事实、未授权效果或未解决的高影响决策均暂停并报告 owner/所需证据，不得猜测放行。实质事实变化使依赖它的旧 Control/路由/授权证据失效。

### 2. 候选预检与真实验证不可混同

候选（如拟写入的受控输出）准备及候选合规预检是应用前门禁，不是已发生效果，也不是最终 Verification。若选择这类路径，审阅准确、有界候选及 manifest/身份；在同一固定 root 和政策下，对完整批次进行新鲜预检。任一已选检查失败、未知、遗漏或过期，都先解决，不得当作通过。随后再核实授权、候选完整性及 baseline，才可应用准确候选。未选择可选候选路径时，记录有事实依据的 Not applicable，且仍须拥有独立授权的实施路径；不得静默回退。

应用收据不证明真实文件/状态与预期相同。应用后读取实际状态并对照收据、路径和当前 baseline；部分完成、冲突、不确定或状态变化时，停止依赖操作，查明当前效果，禁止覆盖后重放。聚焦临时检查只能指导修复并作为初步证据；最终 Verification 属于后续工作流，不得声称候选预检、收据或初步检查已完成最终验收。

### 3. 执行者路由、输出路线与角色各自独立

先遵循用户明确指令，但仍须核验模式、身份、能力、权限、范围和可用性。Single-Agent 模式下 Root 执行；明确要求 sub-agent 与锁定模式冲突时阻断并交 Root 处理，不得自行改模式。Multi-Agent 下依据获授权任务判断 Root 能否胜任；确需 Worker 才从已核实的当前 Session 候选中筛选。Fork 后新 Session 必须重新进入模式/数量门，不能把继承子代理当新候选。候选仅一位时选之；多位时先考虑合格空闲者，仍多位则依任务相关证据比较，不用 transcript 体量或虚构阈值。派发前立即复核身份、权限、角色、能力、范围与最新可用性。无合格候选可报告 new-executor-needed（不是创建授权）；候选忙碌不等于可用。

对每项 Root 直接输出，独立评估输出路由：仅基于请求形式、预期输出量、明确指令、锁定模式及当前证据；不用无关 transcript 体量或任意阈值。结果 `yes`/`no`/`insufficient_evidence`/`failed` 附证据和当前输入、上下文、政策 Hash。过期或 Hash 不匹配是未决，不是 no。`yes` 表示避免 Root 直接物化大型输出；Single-Agent 拓扑下挂起，Multi-Agent 下须有合适空闲 Worker 或等待。它不选择执行者、不授权创建。`no` 仅允许在其余门禁通过时 Root 继续。明确指令只跳过对应建议，其余门禁仍有效。

仅当执行者选择确定需要新 Worker 且输出路线已独立处置，才做角色预留：按获授权任务匹配维护的角色，核查当前 Session 全部已预留/创建角色和容量；只在锁定容量内预留未占用角色。容量不足须 Count Gate 明确批准恰好 +1；不得自动扩额。四种角色全占用、适配/状态未决或无批准则阻断。建议、输出 yes、预留均不创建/派发、不释放 Slice；这些是后续独立门禁。Root 或现有 Worker 执行时，角色步骤可按证据记 Not applicable，不得伪装为预留失败。

### 4. 实施、效果确认与阶段反馈

实施者只检查本 Slice 必需文件，按批准方向作最小改动；不带入无关清理、重构、生成物或外部影响。Worker 仅执行已释放任务并按返回条件报告；Root 持有语义决策和最终验收责任。执行者不得接管未解决架构决策。缺少代码结构证据时可使用定向文本搜索/小范围读取，但不得称为 LSP 证据；结构关系仍未知且属必需条件时阻断。

所有工具调用按实际效果分类，记录输入、目标、授权、输出、错误/isError/exit code、部分效果和可读回证据。`effect=read/check` 是 Agent 对真实行为的声明，不证明命令无副作用，也不授予授权；不能按命令名推断。读操作须检查真实返回；写入、提交或其他副作用要核对目标和范围，完成后尽可能读回实际状态并与调用收据/基线比较。路径应遵守本地精确目标和仓库边界；路径限定不构成 OS 沙箱。失败、超时或工具不可用须如实报告，不得换工具规避授权或门禁。效果未知时先调查真实状态，明确禁止盲目重放。

到达实质阶段边界时提供有界 Progress Signal：进展/当前状态、实际变更范围、偏差与新证据、初步验证/失败、阻塞/需求、未释放边界及下一待决定事项。只提交当前事实，不另造重复进度报告。无触发时记 Not applicable 和原因。单代理的 Control 是内部暂停，不模拟给自己发消息；多代理由 Root 作为父级控制者消费 Worker 反馈并决定是否释放后续工作。Worker 不能自行越过 Slice、扩大范围或释放后续 Slice。

### 5. Control 与回环

到达 Slice 返回条件、实质边界、工具失败或新事实后，Root 结合 Progress Signal 和当前 Unreleased boundary 评估下一动作是否跨接口、schema、兼容性、安全、风险、难以逆转改动、范围或外部影响。需要证据时发出 Evidence-on-Demand 并暂停，取得证据后回到同一 Control；这是中间暂停，不是第四种授权结果。最终只作 `Continue`、`Amend`、`Stop`：

- **Continue**：只有明确且仍新鲜的 Continue 才释放其覆盖的下一个有界 Slice，不授予范围扩张或 Git/外部影响。新 Slice 仍需当前 Context/Decision、四字段及准入核验。任务、授权、边界、相关 epoch 或证据变化若使其不再覆盖，回到 Control 重评；只重核受影响的路线/执行者/角色条件，不重放已完成效果。
- **Amend**：暂停实施，返回 Contract/Decision owner 修订；必要时更新 Context。变化持久化并重新核验后回到同一 Control，取得新的明确 Continue 才可继续。旧 Continue 不释放新范围。
- **Stop**：停止所有依赖动作，保留实际状态与原因，交 Root/用户处理。不得以默认值、建议结果或沉默代替。

路线建议仅作输入。核对当前 Root 状态、直接 owner、适用性、输入/上下文/政策 Hash 和证据时效；建议失败、过期或不可信且直接证据不足时保持未决，绝不默认 Root、no 或 Continue。单代理内部暂停；多代理不得让 Worker 自我批准后续工作。

## 退出与阻断

结束时返回实际完成/未完成状态、精确路径和效果、读回/收据与初步检查证据、失败/部分效果、未决项及仍未释放的边界。仅在本 Slice 返回条件满足、无待处理恢复/效果不明且当前 Control 处置明确时返回；否则返回 needs-prerequisite 或 blocked 并说明缺项。未授权路径或效果、Slice 四字段缺失、冲突/过期证据、必需验证未知、候选守卫未通过、真实效果不明、越界风险或 Stop 均阻断依赖动作。不得把局部实施标为最终完成/验收。

## 重新核验

每次恢复前按变化范围重核事实：Contract/授权/用户指令变化重核受影响 Decision 与 Control；Context、路径内容、文档、Git 或依赖变化使相应证据/epoch 失效；Worker 身份/权限/可用性变化重核执行者；输出输入/政策 Hash 变化重核输出路线；候选、baseline 或应用后状态变化重核候选门禁/效果。只重新核验受影响条件，不重跑完整流程；旧收据、Continue、预检或 Verification 不可越过相关变化沿用。
