所有参与 Agent，包括父级和验证者，在进入/恢复任务时按需使用同一计划上下文；所需内容缺失或过期时刷新。实质进展及带来源事实在适用的阶段、交接、暂停或完成边界记录。同一阶段的相关更新可合并；普通进度汇报及无关小事实本身不触发写入。影响授权、范围、验收、方向或依赖动作的事实，仍须在受影响动作前记录并分析。成功更新本身不要求立即读回；遵循上述保全及结果不明触发条件。

用户需求变化时，先把新指令及来源记录为待分析。再分析其对范围、依赖、验收和方案的影响；持久化分析和修订计划，确认写入操作成功，并在继续前执行本 owner 触发的必要内容核验。之后父级才可授权受影响改动或派发。子上下文收到变化时，在获准贡献范围内提交并返回父级；子 Agent 不能修订 Contract 或释放工作。只有不依赖待处理变化时，才可继续不受影响的已授权工作。
