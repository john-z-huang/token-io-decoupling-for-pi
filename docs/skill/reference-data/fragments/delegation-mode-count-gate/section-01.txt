选择 Multi-Agent Session 后，采用用户明确给出的正整数子代理数量；否则锁定 1 个子代理的预算。首次 Coding 指令默认选择 Multi-Agent 时也应用此默认值。需遵守宿主对数量表示的限制。用户选择了自定义数量选项、但遗漏或给出无效数量时，只提出一个聚焦的补充问题并保持 Mode gate 未放行；不得替换为 1。数量有效时不再提出额外数量问题。其他明确数量无效时，保持路线未放行，直到用户给出有效正整数；不得解释为同意其他数量。数量是完整宿主 Session 生命周期内的子代理总预算，而非每轮、每任务、每阶段或每职责的数量。

路线放行前锁定数量。显式记录空名额时，使用 `agent: unbound`、`role: unassigned`、`slice_status: pending` 和 `lifecycle: pending`；预留名额不表示 Context、Decision 或具体 Slice 已经放行，也不会初始化子代理。预留本身不选择职责，也不因只预留一个名额就自动选择 Primary Output。当前任务上下文和 Decision 审阅完成后，由[子代理职责选择](child-role-selection.yaml)确定职责，再由分配 owner 将其记录到未分配名额中。创建须通过职责和本次 Slice 门禁。Primary Output 的任务限于代码/配置实现或本 Skill 指令/参考文档编辑。普通非 Skill 文档不会触发或消耗预留名额；由根父级编写，包括同时存在代码修改的任务。每项独立职责消耗一个预留名额；复用不增加名额。数量锁定固定的是总预算，不是尚未绑定子代理名额的具体内容。
