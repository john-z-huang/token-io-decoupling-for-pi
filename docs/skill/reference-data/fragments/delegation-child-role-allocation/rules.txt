### 职责分配

在任务上下文和 Decision 完成前，先将锁定数量预留为未绑定、未分配职责的名额。该预留阶段不得仅因只有一个名额就选择或分配 Primary Output；名额保持 `role: unassigned`、`slice_status: pending` 和 `agent: unbound`。Root 审阅当前任务上下文和 Decision 后，使用[子代理职责选择](child-role-selection.yaml)为拟创建子代理确定一个职责；用户明确指令可跳过职责选择建议，但不能跳过 Root 的职责和政策检查。若上下文生成或建议能力不可用，Root 可直接根据当前 owner 和核实事实作出判断。随后在一个未分配名额中预留所选职责，并在创建子代理前放行职责及具体 Slice。普通非 Skill 文档仍由父级编写且不消耗预留名额，即使任务同时包含代码工作也一样。每项独立职责各自消耗一个名额。尚未创建子代理的 unbound 名额可由父级授权在当前数量内调整职责计划，但新职责不得分配给其他任何已预留或已创建子代理。子代理一旦创建，其职责和身份就保持绑定，不得回收或替换。未分配独立 verifier 或辅助职责时，安全情况下可使用当前或已分配 Agent，否则报告不可用；不得通过改名将同一 Session 的工作冒充独立验证。

### Context Bootstrap/Refresh 分配

仅当复用可能比设置成本更有利时分配 Context Bootstrap/Refresh：至少两个独立下游 Worker、广泛侦察加三个或更多路由策略模块，或来源集合大致超过 20k 字符 / 5k token-equivalents。单个小 Worker 或仅文档快速路径应跳过。这里的数值是路由启发式，不是运行时或质量测量结论。
