应用[子代理派发](../references/coding/layer-01-fundamental-concepts/delegation/delegation-child-dispatch.yaml)、[Worker 边界](../references/coding/layer-01-fundamental-concepts/delegation/delegation-worker-boundary.yaml)、[子代理生命周期](../references/coding/layer-01-fundamental-concepts/delegation/delegation-child-lifecycle.yaml)、[子代理复用与替代](../references/coding/layer-01-fundamental-concepts/delegation/delegation-child-reuse-replacement.yaml)、[子代理消息可见性](../references/coding/layer-01-fundamental-concepts/delegation/delegation-child-message-visibility.yaml)、[Content Memo Dispatch](../references/coding/layer-01-fundamental-concepts/context-exchange/content-memo-dispatch.yaml)及[Content Memo Lifecycle](../references/coding/layer-01-fundamental-concepts/context-exchange/content-memo-lifecycle.yaml)。实际已释放 bundle 必须包含完整任务与范围、来源指针、返回条件、适用时准确的授权 Memory 名称，以及显式 `write_content_memo: true` 或 `false`；不得推断默认值。已有稳定身份时只向已绑定的子代理派发已释放 Slice；同步一次性扩展只为 DE05 已批准的未绑定 allocation 发起一次任务调用，并按创建 owner 绑定其真实调用证据。为 true 时遵循 memo owner 生命周期并核验 memo 证据；为 false 时不得派发或写入该 memo。每次 follow-up 均保留实际派发正文证据和当前授权范围。派发或真实任务证据缺失/不完整时阻塞。异步扩展确认派发及显式 memo 值后立即进入 DE07，不提前等待结果；同步一次性调用返回后直接在 DE07 审阅已产生的结果，不模拟异步等待或再次派发。Root 执行时，将子代理派发/memo 记录为有原因的 `not_applicable` 并进入 DE07。派发同时按[任务计划 Memory 生命周期](../references/coding/layer-01-fundamental-concepts/execution-planning/task-plan-memory-lifecycle.yaml)携带准确共享任务计划项目/名称及允许贡献。判断子级需要当前计划读取、直接写入授权，还是仅需有界贡献返回通道；仅提供该角色实际需要的访问。父级协调唯一当前计划写者，并可合并明确授权且有来源的贡献。不得要求每个子级都具备 Memory 写入权限。新事实/进度在 owner 规定的边界纳入；影响授权、范围、验收、方向或依赖动作的变化仍须在该动作前记录。`write_content_memo: false` 不豁免共享计划生命周期。
