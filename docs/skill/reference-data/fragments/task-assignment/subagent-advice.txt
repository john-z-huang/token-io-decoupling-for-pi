从候选中按不透明 `candidate_ref` 选择一个合格子代理，或选择 `insufficient_evidence`。合格要求已核实当前会话身份、职责匹配、所需能力和执行此任务的权限。排除其他会话继承代理和不可用候选。唯一合格候选可直接使用，无需 Decisions。存在多个合格候选时，先考虑适任的空闲子代理，再考虑忙碌者；若都不空闲，等待直到有合适子代理空闲。经过筛选后若只剩一个空闲候选（因为其他合格候选均忙碌），可直接选择该唯一空闲候选。此例外不适用于仍有多个空闲候选的情况。至少有两个空闲候选时，只有建议契约适用于当前会话且出站授权与事实均有效，才调用具体子代理选择 Decisions；能力不适用时由 Root 依据当前 owner 和证据直接比较，不伪造调用身份。若存在合适的空闲 Primary，只向 Decisions 提供该候选和 `insufficient_evidence`；否则提供所有合格空闲候选和 `insufficient_evidence`。若不存在合适 Primary，则比较候选所提供上下文对当前任务的直接支持程度，并优先选择拥有更多相关当前上下文者。不得使用原始 transcript 大小、无关上下文量或数值置信阈值。若上下文相关性相同或无法确认，选择 `insufficient_evidence` 交 Root 审阅。

只有来源政策和当前事实仍然有效时，建议能力失败才可回退到合格的当前会话 `Primary Output` 子代理。回退仍须遵守权限与可用性：仅在其空闲时使用；忙碌时等待其空闲。政策或事实过期、身份冲突时须刷新并交 Root 审阅，绝不回退。若不存在合格 Primary，返回待审阅状态，不得臆造 Root 兜底。唯一合格候选直接使用，无需发送建议请求。多个候选都忙碌时，等待合适子代理空闲。
