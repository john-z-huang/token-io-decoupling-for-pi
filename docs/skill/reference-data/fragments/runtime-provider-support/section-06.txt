Pi 使用的 thinking 控制不等于任意扩展的 effort 参数。只在用户授权和当前工具实际支持时应用设置，并确认扩展接受的值；运行时可能按模型能力收窄档位，不把请求值当作已生效值。不要求子代理自行检查或汇报其模型设置。

依照上面的三模型参考，由Root为获准的新子代理选择模型及可选thinking设置，依据已放行任务的目标、职责、复杂度、范围与依赖、风险、不确定性、验证要求和相关失败事实，在实际受支持的值中选择足够的设置；不按文件数量或角色机械升档。缺少可选设置控制时沿用扩展默认值并记录限制；任务明确要求的设置无法落实时暂停创建，不虚构控制或改用其他模型。

MCP 的 `workflow_select_child_effort` 已删除，不再提供服务端 effort 选择。根据真实 Pi/subagent Schema 选择模型及 thinking；缺少可选控制时记录 `Not applicable`，不得伪造运行时或子模型字段。该限制不影响其他满足契约的通用 API 工具。
