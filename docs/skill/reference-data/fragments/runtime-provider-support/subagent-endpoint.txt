每次创建新子代理前，Root 必须先确认自身当前生效的端点元数据：provider、模型 ID，以及宿主可见的 API 类型/端点路由标识，并记录来源。优先使用当前宿主模型元数据；`PI_PROVIDER`、`PI_MODEL` 仅在确认反映当前有效设置时作为启动证据，切模、reload/resume 后不得用陈旧启动值覆盖当前状态。不得凭模型名称、角色默认值、认证配置存在或 MCP 的 `OPENAI_BASE_URL` 猜测 Root 端点，也不得读取/输出 token、API key、认证头或含凭据的 URL。

子代理的模型节点必须跟随 Root 当前端点：Root 使用 `openai-codex` 时，子代理也使用 `openai-codex`；Root 使用 `openai` API 时，子代理也使用同一 `openai` API 路由。自定义 provider/端点同样沿用已核验的实际映射；相同模型名或相同 API 协议不代表相同路由。端点继承不要求模型 ID 或 thinking 与 Root 相同，下面的任务选型只能在该端点实际可用的模型中进行。

创建前核对真实工具 Schema、provider/model 映射及配置优先级，确保显式参数或经核验的继承行为不会被角色配置、全局默认值或其他路由覆盖。元数据缺失、冲突、无法确认当前值、工具不能保证同端点，或所选模型/档位在该端点不可用时，暂停创建并报告缺口；不得静默切换 provider、API 路由或回退其他端点。端点跟随是创建必需条件，不适用“缺少可选模型控制时沿用默认值”的豁免；不要求子代理自查/自报，也不把这些配置元数据当作可信身份凭证。已创建身份不因 Root 后续切模而重建或重放。
