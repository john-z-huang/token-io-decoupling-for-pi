### 门禁重新进入

同一宿主 Session 生命周期内的后续根指令沿用已锁定的模式和当前子代理数量预算；不重新打开模式选择，也不替换会话选择。后续轮次、compact 或同一 Session 的恢复均不会重置这些门禁。唯一允许的同 Session 数量变化，是按[委派数量门禁](delegation-mode-count-gate.yaml)，在用户实际明确批准为不同且未占用职责增加一个名额后，恰好增加一个名额。该事务只改变数量；不重新选择模式、不放行 Slice，也不创建子代理。其他数量或拓扑变更请求都会阻塞依赖工作，直到开启新 Session。按需更新任务专属 Contract、切片、allocation 的当前生命周期和能力证据。

Fork 会以新的 Session 身份开启新会话。在任何依赖工作前，必须重新确认模式、选择数量并初始化状态记录，即使来源会话曾使用 Single-Agent 模式也一样。继承的子代理身份属于其他会话：不得将其采纳为已创建、已预留、可恢复或当前会话的合格候选。新记录只能依据本会话当前用户指令和状态构建；不得把来源会话已锁定的模式/数量选择冒充为本会话的新选择。

### 更高优先级限制和能力阻断

用户、权限、安全、产品、运行环境、能力、仓库和安全限制始终有效。能力不可用时阻塞路线，不能据此默默改变模式或数量。
